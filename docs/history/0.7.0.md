# 0.7.0: the pipeline engine

Spec: [SPEC](../0.7.0/SPEC.md). Build log: [PROGRESS](../0.7.0/PROGRESS.md). Research notes: [engine extraction](../0.7.0/tevrin-engine-extraction.md). A feature release on 0.6.1, released on 23 November 2026.

0.7.0 shipped in three build PRs: the engine extraction (#50), the SDLC on the engine runner (#59) and the CLI retirement (#60). Tevrin's orchestration is now a reusable engine, and the software lifecycle is its first pack. Users see the same product. The release PR adds the docs and the release date.

## What changed

- **Characterisation first (M54).** The whole SDLC flow runs end to end on the Fake LLM provider, and every transition, gate, artifact and job is snapshotted. The snapshots are frozen: CI fails if one changes (FR-260, FR-261).
- **The engine (M55 to M61).** New projects `Tevrin.Engine.Domain`, `Tevrin.Engine.Runtime` and `Tevrin.Engine.Api` hold the state machine, job queue, gates, artifact store, LLM layer and run log. `Tevrin.Pack.Sdlc` holds the SDLC. An architecture test stops any engine assembly referencing `Aide.*` or a pack.
- **String keys.** Agent, artifact and gate kinds are string keys. Stored and wire values are unchanged, and `openapi/api.json` is byte-identical.
- **Definitions and packs.** A pipeline is a YAML definition with a validator, a canonical hash and named C# extension points. Each run is pinned to its definition hash, so editing the YAML never changes a run in progress. Only `manual` triggers run.
- **One generic state machine.** The old lifecycle machine, phase order, gate table and cascade table are gone. `sdlc.pipeline.yaml` now holds them, and every SDLC transition keeps its unit test.
- **Generic API and UI.** Read endpoints, the timeline, run replay and gate decisions work for any definition. The engine UI adds a Pipeline tab, replay, a gate inbox and a prompt comparison, with no frontend code per pipeline. It lives in `frontend/src/engine/` behind a lint boundary.
- **The SDLC on the engine runner (M62).** All eight SDLC agents run through the engine `AgentStageRunner`. Hooks, context providers, tools, `validate:` guards and stage handlers carry the SDLC's own behaviour. The old agent runner is deleted, and the snapshots and golden prompt tests are unchanged. At start-up, non-final runs pinned to the earlier 0.7.0 definition are re-pinned once.
- **The CLI is retired (M63).** The `tevrin` command, the `aide` alias and their packages are removed. The API and personal API tokens stay. The [Retired CLI](../reference/retired-cli.md) page lists the files and the restore steps.

## Data and API

- New tables `pipeline_definitions`, `pipeline_runs` and `stage_executions`. `state_transitions`, `approval_gates`, `artifacts` and `agent_runs` gain a pipeline run link, and `agent_runs` also stores the redacted input (capped at 1 MB) and latency. All migrations are additive.
- `projects.current_phase`, `status` and `checkpoint` stay, written with the run in one transaction, so a rollback to 0.6.1 still works.
- New read endpoints under `/api/pipeline-runs`, and engine hub events.
- New error code `DEFINITION_UNAVAILABLE` (409): the run's pinned definition names something this build doesn't register.
